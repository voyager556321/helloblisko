# docs/ — idea selection & planning

This folder is the shared space for picking what we actually build at Hack Year 2026, before the
official task is revealed and while we're narrowing it down afterward.

## Process

1. **Brainstorm** — everyone adds candidate ideas/topics to [`ideas.md`](./ideas.md), one entry
   per idea. Rough is fine; the point is to get options on paper, not to polish them.
2. **Discuss** — add thoughts, questions, and concerns directly under each idea in `ideas.md` (or
   open a PR comment thread on this doc). Flag feasibility issues, team-fit, or overlap with the
   confirmed task early.
3. **Decide** — once we converge (or once the real task is revealed and narrows our options), the
   chosen idea and the reasoning get recorded in [`decision-log.md`](./decision-log.md). Keep
   rejected ideas in `ideas.md` rather than deleting them — useful if we need to pivot later.
4. **Plan** — once an idea is selected, sketch the implementation plan in
   [`implementation-plan.md`](./implementation-plan.md): scope for the demo, who's doing what,
   what's cut if we run out of time.

## Files

- `ideas.md` — all candidate ideas, in progress or rejected
- `decision-log.md` — what we picked and why
- `implementation-plan.md` — scope, task breakdown, and cuts for the selected idea

See `CLAUDE.md` at the repo root for the platform/architecture decision — this folder is about
*what* we build, not *how* the codebase is structured.
